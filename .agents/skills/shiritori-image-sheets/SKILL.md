# しりとりの16語画像シート

単語画像の大量追加・補完では、このユーザーの指定として**16語を1枚の4×4シート**で生成する。通常の画像作成スキルに「1素材1回」とある場合も、このシート方式の明示的指定を優先する。専用画像16回の生成に戻さない。既存の意味が一致する画像の再利用、数式・色値による正確な図の生成も選択肢に含める。

**大きな余白は不要。** 各コマ内で絵を大きく使ってよい。合格条件は実測した罫線とその縁が除去され、他のコマが混入せず、コマ内の絵を任意の割合で削らないこと。中央50%に絵を縮める、周囲5%を白くする等の条件を追加しない。

## 選定と生成

- 現在の辞書から未掲載語16語を選び、ID・読み・見出し・語義・難易度・出力名・コマ番号を保存する。古いIDや前回の残件数をそのまま使わない。同音異義語は語義で区別する。
- しりとりリポジトリの既定候補は `C:/Users/user/hiragana-ninshiki`。実際の作業場所、Git状態、最新の登録・確認方式を確認する。詳しい接続箇所は [references/integration.md](references/integration.md) を読む。
- 組み込みの ImageGen で**1シートにつき1回**生成する。CLI/APIへ勝手に切り替えない。生成指示の具体例は [references/sheet-prompt.md](references/sheet-prompt.md)。
- 4×4、左から右・上から下の16語。外枠を含む縦5本・横5本の連続した純マゼンタ `#ff00ff` の罫線を指定する。罫線は全体の0/25/50/75/100%付近に置く。マゼンタは罫線専用。文字・番号・ラベルは絵に入れない。
- 絵・背景・影は自分のコマ内に収める。画像が枠を越えないことを要求するが、余白の割合は指定しない。一般的な絵本風の明瞭なイラストを使い、実物の形や数が重要な語では必要な根拠を確認する。
- 元シートと全プロンプトを保存する。生成結果がローカルファイルとして得られた場合はその出力を使い、画像のbase64をテキストに出力しない。

## 自動切り出し

同梱の [scripts/crop-shiritori-grid.py](scripts/crop-shiritori-grid.py) を使う。Python・Pillow・NumPyが必要。実行環境が不明ならCodexの依存ランタイムを確認する。

出力名16個は語IDを含む安全な名前にする（例：`wave7-word-1143`）。`--names` は計画のコマ順から機械的に作る。手入力で順を入れ替えない。

1. 元シート、`--names`、新規の `--output` ディレクトリ、`--report` JSONファイルを指定して実行する。
2. 成功したら16コマをまとめて保存する。失敗時は画像を登録しない。等分の座標・固定率のトリミング・目視座標へのフォールバックは禁止。
3. 罫線の本数・連続性・位置・線幅・コマ寸法・罫線色の残り・空コマを機械判定する。薄い罫線色は実測して除去する。絵の周囲が白いかどうかは合格条件にしない。
4. 256×256へ縦横比を保って収める。縦横比を変えるリサイズや、画面を埋めるための絵の切り捨てをしない。
5. JSON記録には原画像のハッシュ、実測境界、コマ順、切り出し座標、PNGハッシュを保存する。`edgeInkFraction` は診断用で、大きな余白を強制する値ではない。
6. 登録前に `verify_report(report_path, source_path, output_directory)` または `--verify-existing` で元シートから再計算し、16枚の出力まで一致を検証する。既存画像・検証記録の上書きは行わない。

罫線のないシートや曖昧な境界は再生成・編集で直す。余白不足を理由に再生成しない。生成で自分のコマ内に描かれた内容の誤りは切り出しでは修復できないので、必要なコマの内容を修正する。

## 登録と確認

- 語義と絵の内容を照合する。**切り出し位置の合否は機械検証**で決め、意味・被写体・構造の確認とは分ける。内容まで自動で正しいと判断したことにしない。
- 登録は既存のインポーターで行い、語義・順序・難易度・既存画像を維持する。登録前に全対象を検証し、途中だけ辞書を変更しない。
- 原シート、プロンプト、語ID・語義、検証JSON、内容の確認、画像マニフェスト、全共有先、辞書履歴、確認カタログを同期する。共有は同じ対象・意味だと確認できる語に限る。
- 画像参照と語義・登録履歴を検証し、追加語がゲームと画像確認画面でPC・スマホに表示されることを確認する。余白の多寡を不具合として扱わない。
- 追加数と未掲載数を現在の辞書から数え、保存場所と検証結果を報告する。コミット・プッシュ・公開をこのスキルだけで承認済みとは扱わない。

処理を変更したときは `python -B scripts/test-shiritori-grid-crop.py` を実行する。旧 `magenta-grid-white-guard-v1` 記録の再検証互換性は残すが、新しい生成・切り出しは余白条件のない `magenta-grid-lines-only-v2` を使う。
