# 一般語・複合語を継続して増やす台帳

## 採用方針 v2（2026-11-16）

ユーザー指定：**「基本的に、不適切でなければ採用しましょう。難しくてもオーケーです。」**

難語・専門語・稀語・古語・方言を採用対象にする。学年4・5や、一般的でないことを理由に保留しない。
実在する表記と読み、今回説明する語義を照合でき、不適切な内容を含まなければ登録する。
学年の個別確認を終えていない追加語はレベル4に置き、採用と低学年CPUへの出題を分ける。
古語・方言・古い漢字などは用法を付記する。旧仮名遣いは現代の発音と混同しない。

全名詞を対象に走査するため、以前の一般語・生活系列だけの候補数より対象が広い。
出典内の同音異義語の取り違え、根拠のない読み、不適切な語義は、難語の許可とは別に扱う。
詳細は `adoption-policy.json`。v2の追加・検証結果は
[採用範囲拡大の記録](../../docs/shiritori-broad-adoption-2026-11-16.md)を参照。

対象は通常辞書。日本の地名・駅名の任意パック95,520項目は別集計。

## 継続する手順

1. `git fetch origin` で最新参照を確認する。作業中の変更が多い場合は最新mainから独立した作業ツリーを作る。
2. `python -B -X utf8 scripts/audit-shiritori-lexical-families.py` で、生活場面64系列と一般語を出典に照合する。
3. 未収録候補から、一般的な**読み**を優先して個別説明を編集する。見出しが一般的でも、すべての別読みが一般的とは扱わない。
4. `editorial/` に編集原稿、`decisions/` と `data/dictionary-imports/*.review.json` に採用・既存・保留理由を残す。
5. `python -B -X utf8 scripts/expand-shiritori-lexicon.py --apply` で、新たに追加した語から関連形・複合語を繰り返し取り込む。追加可能な候補が0になるまで続く。
6. `python -B -X utf8 scripts/walk-shiritori-related-words.py` で参照語・反対語・逆参照をたどり、新たに見つけた語も次の起点にする。
7. source evidence、配信、学年、取り込み履歴、PC・スマホの検証を行う。

`expand-shiritori-lexicon.py` に `--apply` を付けなければ、次の具体的な追加便を作成して止まる。
登録便の再実行は追加0件。途中で止まった登録は、辞書のハッシュと履歴を確認して仕上げを再開できる。
過去の訂正で廃止された表記は復活させない。

## 芋づる式走査の記録

`related-seen.json` に走査済みの出典項目と発見経路を保存する。
出典の項目ID、親の項目ID、参照関係、深さを残し、走査を繰り返しても既知の語を失わない。
現在は約6.1万項目を走査し、深さ7までの到達可能な参照関係をたどった。
これは日本語全体の網羅ではなく、今回の資料で到達できた範囲。

v1公開時点の未精査候補は `related-queue.jsonl` の **56,740組**だった。
v2では全名詞へ対象を広げて再計算するため、最新件数は `related-checkpoint.json` を参照。
辞書に実在する候補というだけで、児童向け・一般語・採用可能と確認した数ではない。
参照の解決できなかった箇所も `related-checkpoint.json` に記録する。

## 採用条件

- 読みだけで既存判定しない。読み＋表記＋意味を区別する。
- 同義語は同音だけで結び付けない。読みと漢字と語義の適用先を守る。
- 別表記の説明継承は単一名詞語義と出典の対応を確認する。
- 異なる出典項目の同義関係は、全英語語義集合の一致などを記録する。一つの多義的な英単語だけでは同義と判定しない。
- 複合語は実在する独立見出しを必須とする。構成語の品詞、複合語と構成語の英語語義の対応も確認する。
- 「旗艦店」「埋葬者」など、接尾辞の直訳で誤る例は個別訂正か保留にする。
- WordNetの英語見出しが一致しただけの説明は自動採用しない。英語の対応が一意になる根拠を、採用先のJMdict項目ごとに確認する。同じ読みの別項目の根拠を流用しない。
- 一括選定の説明は暫定レベル4に保つ。一般語としての優先表示と低学年CPUへの採用を混同しない。

## 保存するもの

| ファイル | 内容 |
| --- | --- |
| `adoption-policy.json` | 難しさを除外理由にしない採用方針 |
| `families.json` | 生活場面・複合語の系列と展開軸 |
| `family-coverage.json` | 系列別の表記上の収録状況。語義網羅率ではない |
| `summary.json` | 現在の辞書ハッシュ、出典ハッシュ、件数、限界 |
| `editorial/`、`decisions/` | 個別原稿と採否の判断 |
| `compound-editorial.json` | 構造照合で間違える例の訂正・保留 |
| `related-seen.json` | 継続走査の履歴 |
| `related-checkpoint.json` | 現在の関連語走査の件数と未解決箇所 |
| `expansion-checkpoint.json` | 繰り返し取り込みの到達点 |
| `alias-meaning-holds.json` | 意味の再確認が必要な候補 |

大きな `queue.jsonl`、`related-queue.jsonl`、`*-candidates.jsonl` はローカルの再生成用キャッシュ。
採用記録・保留・要約・発見経路はGitに保持する。ゲームはこれらの管理台帳を丸ごと読み込まない。
