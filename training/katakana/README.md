# カタカナの濁点・半濁点の自動合成

`etl5_train_marks.ipynb` をColabへアップロードし、上から実行します。
合成・学習コードを埋め込んだ単独ノートブックなので、Pythonファイルのアップロードは不要です。
元の２冊、元モデル、公開アプリは変更していません。

画像はZIPにまとめ、Colab左側のファイル欄からアップロードしてください。
DriveのダウンロードでZIPが３つなどに分割されても、まとめ直しは不要です。
分割ZIPをすべてアップロードすると③の `ZIP_PATHS` が自動検出し、③.5で同じ画像フォルダへ展開します。
無関係なZIPがある場合だけ `ZIP_PATHS` へ使用するファイルのパスを明示します。
`processed_dataset/ｶ/*.png` のように親フォルダがあるZIPも、`ｶ/*.png` から始まるZIPも扱えます。
ZIPには１つの画像データセットだけを入れます。元画像・前処理済み画像の両方に対応します。
④の監査・⑤のプレビュー・⑥の学習・⑦の合成テストは、このローカルコピーを読みます。
DriveのPNG一覧取得や１枚ずつの転送は行いません。
展開は1,000枚ごとに進捗を表示し、再実行時は同じZIPの展開済み画像を再利用します。
保存する最良モデル・エポック履歴・評価結果はDriveのままです。
Colabランタイムが破棄されるとZIPと展開画像は消えるため、その際は再アップロードします。

学習にはColabに同梱されたTensorFlowを優先して使い、2.19.0へダウングレードしません。
TensorFlowが存在しない環境だけ、2.20以上の対応する安定版を取得します。
最初のセルにPython・TensorFlowの版とGPU一覧を表示し、準備に失敗したらそこで停止します。

## 入力と出力

- 入力: 元ノートで使った `processed_dataset/ｶ/*.png` 等。全角フォルダも可。
- 初期モデル: 元の `model_katakana/model.h5`。特徴抽出層と清音46出力を引き継いで72出力へ拡張。
- 新しい出力: `model_katakana_marks_v2_close_spacing/`。旧v1とは別のフォルダです。
- 対応: 清音46 + 濁音20 + 半濁音5 + ヴ = 72文字。小文字・長音の直接認識は今回の対象外です。
- 自動合成: 揺らぎを持つ２本の線または輪を描画し、元の文字に接触しない位置へ配置。
  位置・大きさ・角度・線幅・輪の縦横比を変えます。フォントや生成AI画像は学習に使いません。
- 任意: 自分で用意した手書きの点を、分割済みのmark bankから合成できます。

`synthesis-demo.png` は合成処理の説明用にフォントから作った図です。ETLの実筆や認識結果ではありません。
実際のデータのプレビューはノート内で生成します。

### 配置v2（2026-10-18）

旧配置は、点の長方形全体が本体と離れるまで右・上へ移動するため、字によって点が遠くなりました。
v2は長方形の空白を無視し、実際の墨線同士の距離で位置を選びます。
144pxの合成面で80%は3〜6px、20%は7〜11pxの目標距離を無作為に選び、目標〜目標+1pxを満たす右上付近へ置きます。
距離は画素間のチェビシェフ距離で、最終64px化の前の値です。最も近い設定でも墨線間に空白を確保します。
点の空白部分で元の筆画を消さず、墨線を最大値で重ねます。手書きの点を使うMARK_BANKにも同じ配置を適用します。
この比率は実筆から推定した値ではなく、近い配置を増やす今回の実験条件です。実筆の近い例・離れた例で確認してください。

Colabでは更新したノートを開き、②のモジュールから⑤のプレビュー、⑥の学習を再実行します。
既定の出力先はv2専用なので、新しい実験として旧モデルを初期値に学習します。
合成器の版を変えており、v1の画像キャッシュや再開状態は流用しません。v1のOUTPUT_DIRへ戻さないでください。
すでに実行中のColabには自動反映されません。

## 添付コードから確認できたこと

- 学習ノートの46文字順と最終GraphModel出力のサイズが、現アプリのモデルと一致します。
  バイナリ内容の同一性までは検証できません。
- 前処理ノートは元のファイル名を維持して切り抜き・拡縮し、枚数は増やしていません。
- 元の学習ログの各文字2,800枚の由来は、この２冊からは確定できません。
- 元の前処理は余白なし・NEAREST、現アプリは85%の大きさ・ブラウザ補間です。
  今回は85%に寄せますが、Pillowとブラウザの補間はピクセル単位では一致しません。
- `ModelCheckpoint(save_freq=10)` は10エポックではなく10バッチごとの保存です。
  今回はエポック終了時にモデル・optimizer・実行状態を保存し、完了したエポックから再開します。
  最良モデルとEarlyStoppingの待ち回数も引き継ぎます。エポック途中の位置は復元しません。

## 分割と評価

学習・検証・テストは合成前に80/10/10のグループ分割を行います。
標準は `CONFIRM_ONE_PNG_PER_ORIGINAL=True` です。元からある画像を使うというユーザーの確認に基づき、
CSVなしで原画像ごとに分割して学習できます。
`groups.csv` は任意で、筆記者別の評価を行う場合や、あらかじめ増幅済みの画像を入力する場合に使います。
その `path,group` に同じ筆記者または同じ原画像の派生をまとめます。
同じグループの清音・濁音・半濁音が異なる分割へ入ることはありません。
完全一致の画像の除外、グループ欠落・衝突、各文字各分割の欠落も検査します。
筆記者グループが少ない場合は分割できず停止することがあります。

原画像単位の評価と、筆記者を分離した評価は別です。筆記者IDの追加収集は学習の必須条件ではありません。
由来不明なら `ALLOW_UNVERIFIED_GROUPS=True` で診断用の実行は可能ですが、
変形した同一原画像が評価へ混ざるおそれがあり、独立した精度として報告できません。

検証分割だけで最良モデルを選び、テスト分割は別に評価します。
Top1・Top5、文字別Top1と件数、混同行列、同じ清音入力での旧モデル比較を保存します。
**合成テストでの高い値は、実際にガ・パと書いたときの精度を意味しません。**
実筆テスト用セルもあります。文字ごとの未評価項目を記録します。

実筆画像は [収集アプリ](../../handwriting-capture.html) で用意できます。
そこで出力する `real-katakana-....zip` をColabへアップロードし、⑧の `REAL_ZIP` に指定します。
`REAL_ZIP = None` のままでも、`/content` に該当ZIPが1つなら自動検出します。
見つからない場合・複数ある場合・ひらがなのZIPを指定した場合は案内して停止します。
⑧は開始、使用ZIP、評価枚数、Top1／Top5、文字別結果と保存先を表示します。
濁音・半濁音を数文字だけ集めたZIPでも評価できます。
詳しくは [収集アプリの使い方](../../docs/handwriting-capture.md) を参照してください。

初回の合成は時間がかかります。TensorFlowのローカルディスクキャッシュを利用し、
以降のエポックでDriveから画像を読み直すことを避けます。データ規模によって数GB必要です。
各エポックのモデルは履歴として残します。ランタイム終了後は画像キャッシュのみ再生成します。

## 変換とアプリへの反映

任意の変換セルは、学習環境を変更しない独立したvenvへTensorFlow.jsコンバータを入れます。
変換用venvにはuvでPython 3.12を用意し、学習ランタイムのPython版と分離します。
SavedModelからGraphModelへ変換し、重みファイルの存在を検査します。
⑩は子プロセスの標準出力とエラーを画面に表示し、出力先へ `converter-install.log`、
`converter-versions.log`、`converter-日時.log` を保存します。失敗時は変換ログ末尾で原因を確認します。
変換時に `labels.json` と入力仕様も出力します。
`model.json` と全重みファイルに加え、アプリのラベル順を72文字へ合わせる必要があります。
旧アプリの46文字ラベルのままモデルだけを置き換えないでください。
