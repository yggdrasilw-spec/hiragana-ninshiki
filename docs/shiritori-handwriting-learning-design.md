# しりとり手書き入力と、かなの書字フィードバック

## 目的と現在の到達点

子どもがアプリ内で１語を続けて書き、字の形を確かめ、必要な１文字だけを書き直せることを目指す。OSの画面キーボードへ切り替える方式ではない。

現在の実装は読み取りの試作で、字形の正誤判定は未実装。既定は従来の１文字入力。設定の「文字・入力 → てがきの よみとりかた」で切り替え、保存できる。新方式はひらがなのみ。カタカナでは従来方式を使い、ひらがなへ戻すと選んだ方式に戻る。カタカナの濁点・半濁点モデルや学習用ファイルは変更しない。

読み取りに使うのは既存の１文字モデル。座標から線幅をそろえた画像を生成し、左から右への複数の区切りを評価する。辞書やしりとりの先頭文字で筆跡を都合よく補正しない。大きさの情報を残し、小さい字・通常の字の両候補を作る。これは専用の複数文字モデルや字形検査を実装したことを意味しない。

目視レビューのため、選択した候補の１文字ごとの筆跡範囲を色付きの矩形で表示する。「1:り」のような番号・文字を添え、下の文字ボタンにも同じ番号・色を使う。候補を切り替えると区切りも切り替わり、文字の修正時は対応する枠を強調する。従来の１文字入力でも読み取り範囲を表示する。枠は正しさを示すものではなく、分類に使った筆跡のまとまりを示す。描画は別のSVG層で行い、認識用画像には混ぜない。

「書いた順・向き」を設定または入力欄のボタンでオン・オフできる（初期はオフ、選択を保存）。始点・終点・実際に書いた画の番号・方向矢印を別のSVG層に表示し、全体を再生できる。文字ボタンを選ぶと、その文字だけの拡大表示と再生が使える。画の番号は各文字で１から数え、単語全体の通し番号は表示しない。文字の切り分けが未確定の間は、まとめ書き欄には画の番号を出さない。後から付けた濁点も実際の時系列順に表示する。再生は確認しやすい速度に調整し、実際の筆記時間を完全再現するものではない。新しい描画、クリア、モード変更、オフ操作、ダイアログを閉じる操作で再生を停止する。表示・再生は認識用キャンバスを変更しない。

## 一筆アプリから受け継ぐ原則

一筆アプリの `shape/engine.mjs`、`shape/policy.mjs`、`shape-rules.mjs` を参照した。次の３つは分けて扱う。

1. **文字としての成立**：必要な線・曲がり・結びなどがあり、別の字や字でない形になっていないか。
2. **今回の書き方の課題**：書き順・向きなど、その練習で明示した目標を達成したか。
3. **より整える助言**：中心・間隔・見栄えなど。これだけを理由に文字を不正解にしない。

漢字用の部品・直線の判定や閾値を、かなにそのまま移植しない。かなの曲線、結び、筆記体と印刷字体の違い、許容される手書きの変形に対応する規則が必要。

## 児童の操作

1. 枠のない欄に「りんご」のように１語を書く。手を止めるか「よみとる」で候補を表示する。
2. 読みが違うときは「何を書いたつもりか」を選ぶ。この選択は字形の合格ではなく、確認する文字の指定。
3. 文字としての成立を１文字ずつ確認する。問題があれば、その文字と実際の問題箇所を色で示す。
4. 「ここをつなげよう」のような助言を１つだけ示す。残りは大きな１文字練習欄で確認しながら書き直す。
5. 問題のあった１文字だけ再確認し、ほかの筆跡は保持する。最後に「けってい」でしりとりへ送る。

最初はお手本なしで書く。書き直し時は、お手本と自分の字を並べ、対応が確かな部分だけ色で示す。なぞり・１画目のヒント・お手本を見ての書き直しは、支援ありとして扱う。

現在の候補一覧・ひらがな一覧からの文字修正は、読み取り試験用の操作。将来の書字練習では、候補選択で問題のある筆跡を合格へ変えない。選んだ文字を対象に元の筆跡を検査し、必要なら書き直す。教師が進めた場合は、教師確認として区別する。

## 判定を分ける

| 状態 | 扱い |
| --- | --- |
| 読み取り候補 | 意図の候補。学習上の正解にはしない |
| 字形を確認できた | 承認・校正済みの必須条件を満たした範囲で通す |
| はっきりした字形上の問題 | 根拠となる箇所と１つの助言を表示し、対象の字を書き直す |
| 判断が難しい | 不正解とも合格とも決めず、お手本比較・書き直し・教師確認へ回す |
| その字の判定が未対応 | 未判定として扱い、自動合格にしない |

分類器は、字でない入力でも何らかの文字を返しうる。モデルの確率や候補間の差を「正しく書けた度合い」にしない。別の文字として成立する筆跡なのか、線が不足した形なのか、切り分けの失敗なのかも分ける。

全体の字形判定を通すには、必要な規則すべてについて確認できることが必要。１つの規則が通っただけで、未対応の規則を無視して合格にしない。未承認・未校正の規則は試験結果として残し、自動の正誤に使わない。

## かな固有の確認

- 「め／ぬ」「る／ろ」：結びの有無など、文字を区別する特徴。単なる見栄えと分離する。
- 「き／さ」「は／ほ」：線・曲線の関係を確認する。画数だけの一致では判断せず、許容されるつながり方も扱う。
- 濁点・半濁点：本体と印の位置・数・形を確認する。後から付けた印も同じ文字へ対応づける。対応が不確かなら判定を保留する。
- 「ゃ・ゅ・ょ・っ・ぁ・ぃ・ぅ・ぇ・ぉ・ゎ」：基本形の検査と、周囲に対するサイズ・位置の検査を分ける。１文字を64×64へ拡大した画像だけでは大小が消えるので、元の単語内の座標を必ず使う。
- すべての文字を小さく書いた場合や、１文字しかない場合は、絶対的な小ささだけで小文字にしない。
- 小文字の意図を選んだのに通常サイズで書いてある場合は、選択だけで通さず、隣の字との比較を示して書き直す。
- 「っ」が大きいが語としては「きって」が自然、という理由だけで小文字へ自動修正しない。
- 書き順・はね・はらいの課題を、文字として成立するかの判定へ無条件に混ぜない。端末の点の抜け、左利き、ペンを離した補筆も考慮する。

## 根拠のあるフィードバック

文字ごとの規則データは、規則ID・版、対象文字と許容変形、見る特徴、児童向け助言、問題箇所、資料・権利情報、人手レビュー状態、実筆跡の校正状態を持つ。筆跡とお手本の線の対応が確かでないときは、場所や「○画目」を断言しない。

`strokeId` を持つ筆跡のスナップショットと、区切りの候補・大小判断に使った座標を保持する。表示用と判定用の画像を分ける。１文字の書き直しは、その文字に対応した筆跡を差し替え、対応が曖昧な隣接文字・濁点も再評価する。非同期結果は筆跡・文字意図・規則版の一致を確認してから反映する。

学習記録を追加する場合は、読み取り結果、字形結果、書き方の課題、お手本やヒントの使用、自己確認・教師確認を別に記録する。美文字の助言だけで自力正解や復習予定を変更しない。筆跡は既定では端末内で処理し、外部へ送らない。

## 検証と導入順

まず、字を区別する根拠を説明できる少数のひらがなから試す。正しく書いた児童の字・許容変形・別の正しい字・線を抜いた字・余分な線・左右反転・誤った結び・濁点の欠落・大小の間違い・字でない線を対にして検証する。児童・筆記具・端末が別の評価用データを確保し、学習・閾値調整用のデータから分離する。

評価するのは正しい字の受理率だけではない。誤った字の誤受理率、正しい字の誤拒否率、保留率、助言の部位と内容の正しさ、書き直して改善した割合を文字・問題別に報告する。認識候補への含有率と字形の合否を別に集計する。基準は実測と教材上の許容範囲から決める。

現在の幾何学的な作図サンプルでは、区切り調整後「くし」「しし」「くり」「りんご」は先頭候補に出た。「きって」は５候補内に入り、「きゃく」は入らない。これらは開発者が作った少数の線で、児童の筆跡でも字形判定の検証でもない。広い認識率や教材としての完成度を表す数値にはしない。

次の段階は、①１文字フィードバック画面と状態管理、②少数のかな規則と正例・誤例レビュー、③単語内での疑わしい文字だけの書き直し、④実筆跡での校正、の順に進める。現在の「１もじずつ」へ戻す設定は維持する。

## 細かな字形の助言を別の検証画面で育てる

丸み、折れの角度、線の長さ、突き抜け、はね、字全体の縦横比、結びの扁平さなどは、共通の距離スコア１つで評価しない。「どの文字の、どの部分に、どの許容範囲を適用するか」を規則として持つ。自分の筆跡・お手本・注目箇所・助言を並べる独立したかなの検証画面を先に用意する構成が適する。現在の実装にこれらの自動助言は含まれない。

| 観点 | 検証画面で扱うもの |
| --- | --- |
| バランス・長さ | 対応する線同士の比率、重心、相対配置。文字を成立させる条件と、整える目安を分ける |
| 突き抜け | 対応する線の交差と、その先の長さ。字の区別に必要な条件かを資料で確認する |
| はね | 終筆付近の向きと局所形状。文字・書き方の課題に応じて必要性を設定する |
| 丸み・折れの角 | 局所の曲率や方向変化。指や端末の点の粗さを、字の癖と取り違えない |
| 細長い外形 | 文字全体の縦横比と内部配置。縦横を別々に正規化して情報を消さない |
| 結びの扁平さ | 結び部分を対応づけ、その局所の縦横比と接触を確認する。字全体をつぶす指示にしない |

学習者への表示は「ここを、少しだけ丸くしよう」のように１点ずつ。直す箇所を色で示し、適切な場合は許容範囲の帯・比較線も表示する。対応する部分が見つからなければ、具体的な誤りを推測して指摘しない。お手本の形を唯一の正解にせず、許容される手書き変形を含めてレビューする。

検証画面としりとりは、同じ座標データ・規則データ・評価エンジンを利用する。エンジンは文字、筆跡、字内と単語内の座標、規則版を受け取り、結果・根拠・注目箇所・助言を返す。しりとり固有の辞書や勝敗処理には依存させない。文字ごとに正例・誤例の対と人手レビュー結果を残し、確認できた規則を版付きで取り込む。別アプリ全体を完成させるまで待つ必要はなく、少数文字で確認した機能から段階的に輸入できる。

## 検証画面の最初の実装

`kana-feedback-lab.html` / `.mjs` / `.css` と、UIから独立した `kana-feedback-engine.mjs` を追加した。お手本はひらがな86字。事前の文字選択をなくし、１字を書いて既存の71クラス認識モデルに渡し、読み取り結果を本人が確認してからお手本に接続する。小さい字は通常字に併記し、モデルにない字も読み取り後に全字一覧から選び直せる。１字だけで小さい字の意図や大きさは確定しない。筆跡とお手本を並べ、書いた順と向き、お手本の重ね表示、比較した箇所の着色を利用できる。しりとりの「文字・入力」設定にリンクがある。

現在の助言候補は、字全体の縦横比、線同士の相対長、し・つの角ばった曲がり、線の対応に基づく順番・方向の観察。数値のしきい値は試作用で、教材上の合否基準ではない。対応する線を確認できないときは詳細な助言を保留し、対象外の文字・点・線の不足も自動合格にしない。「助言なし」も合格ではない。突き抜け、はね、結びの扁平さなどの規則と、小文字の単語内評価は未実装。

参考線データは `data/kana-feedback-reference.json` に収録。KanjiVG / Ulrich Apel、CC BY-SA 3.0。既存のかなデータからひらがな86字を抽出し、SVG path文字列は変更せず、表示と比較時に点列化・拡大する。元データのハッシュ、出典URL、ライセンスURLと変更内容を記録し、画面・JSON出力にも帰属を表示する。再抽出は `node scripts/build-kana-feedback-reference.cjs <kana.json>`。

人手のレビューは「筆跡の扱い」「助言の評価」「メモ」と筆跡・参考線・観察結果・エンジン版を一緒に、端末へ最大100例保存できる。JSONとして出力可能。比較用の作図例は必ず作図例と表示し、児童の実筆跡や校正済み正例・誤例として扱わない。筆跡を書き足したり例を切り替えると、以前の助言とレビュー評価を破棄する。

検証：`node tests/kana-feedback-engine.test.mjs`、`node tests/kana-feedback-lab-browser.cjs`。単体検証では平行移動・等方拡大に対する不変性、逆向き、順序違い、相対長、丸み、外形、点・落書き・対象外の保留、合格を返さないことを確認する。ブラウザ検証では３画面幅で86字のお手本、実モデルによる読み取りと選択、逆向き・線の不足例、実ポインター入力、助言の更新、方向表示の切り替え、保存・JSON出力を確認する。これは児童の実筆跡での精度検証ではない。

児童向けの助言は「かく むき」「せんの ながさ」「もうすこし たてに ながく」などに統一する。数値・線の対応・助言の校正状態・記録操作は、折り畳んだ先生・開発者用の欄に置く。全字対応でも合否判定を追加せず、未校正の観察として扱う。線の対応付けは上位２経路を保持する部分集合DPにし、濁点などで画数が増えても階乗の探索を避ける。
