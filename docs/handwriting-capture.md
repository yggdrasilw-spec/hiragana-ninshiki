# 実筆画像の収集

`handwriting-capture.html` をHTTP(S)で配信してブラウザで開きます。
収集画面は `kana-models.js` とモデルファイルを使います。認識・追加学習にはTensorFlow.js（初回CDN取得）が必要です。
通信できない場合も画像の収集・保存・ZIP出力は使えます。
スマホで利用する場合は同じファイルを配信するHTTP(S)ページを開きます。

1. カタカナ／ひらがな、文字のセット、１文字あたりの枚数を選ぶ。
2. 表示された文字を指・ペン・マウスで１文字ずつ書き、「保存して、次へ」。
3. 「画像をZIPで保存」で現在の記録ID・文字種類の全画像をダウンロードする。

カタカナは清音46＋濁音20＋半濁音5＋ヴの72文字、ひらがなは既存モデルと同じ71文字です。
初期設定はカタカナの濁音・半濁音26文字を３枚ずつ。文字ボタンで好きな文字へ移動できます。
進捗は保存した実際の枚数だけで計算し、スキップしても完了扱いにはしません。

筆跡と保存画像はIndexedDBで端末内に保存します。書きかけは文字・記録IDごとに保持します。
新しい人の記録は「新しい人」で開始し、以前の記録IDは入力欄の候補から選び直せます。
名前などの個人情報は不要です。ネットワークへのデータ送信は行いません。
ブラウザ保存が使えない場合は画面に表示し、その場でZIPへ書き出せるようにします。

## ZIPの内容

```text
ガ/<sample-id>.png
パ/<sample-id>.png
strokes/<sample-id>.json
manifest.json
README.txt
```

PNGは白背景・黒文字の256×256。補助線・お手本・案内文字は入りません。
元の正方形全体を保存し、切り抜きや64px化は評価ノート側で行います。
筆跡は0〜1の正規化座標、筆画内の経過時間、pointer種別、線幅を保存します。
manifestには正解文字・画像パス・記録ID・入力方法などを保存します。
ZIPのUTF-8パスとCRCは標準形式で、外部ZIPライブラリへの依存はありません。

## Colabで実筆評価

収集した `real-katakana-....zip` をColabへアップロードし、
`training/katakana/etl5_train_marks.ipynb` の⑧で次を設定します。

```python
REAL_ZIP = '/content/real-katakana-....zip'
```

⑧がZIPをローカルへ展開して評価します。全72文字がそろっていなくても評価でき、
未評価の文字を結果に残します。`real-` で始まるZIPは学習データの自動選択から除外します。
実筆テストに使った画像を追加学習へ使う場合、別の画像をテスト用に確保します。
ひらがなの収集ZIPは作れますが、今回の学習ノートの評価対象はカタカナです。

## モデル比較・苦手文字のテスト（2026-10-19）

ひらがな71文字、カタカナ72文字を使用します。
しりとりと手書き比較画面のカタカナは、`tfjs_model/katakana-marks-20261018/` の濁点・半濁点つき72文字モデルを使用します。旧46文字モデルは選択肢から廃止しました。
しりとりは複数文字の自動認識が標準です。設定でオフにすると１文字ずつ認識できます。

1. 「試すモデル」を選び、文字を書いて「今の筆跡を認識」で上位5候補を確認。
   モデル一覧にはひらがな・カタカナを常に表示し、選択に合わせて収集する文字種類も切り替えます。
2. 用途「評価用」で、通常の文字も含めて普段どおりの筆跡を保存。
3. 「保存画像でモデルを比較」で現在の記録ID・文字種類の評価用画像を一括評価。
4. 文字別の正解数、間違えた候補、上位3候補の一致数を確認。「比較結果JSONを保存」で記録を取り出す。
5. 「評価で間違えた文字」で選択中モデルの苦手文字を追加収集。まだ誤認識がない場合は濁音セットを表示。

ラベルにない文字は「対象外」として別集計し、正解率の分母から除きます。
比較の分母と対象外枚数を確認してください。認識結果は書字の正しさの採点ではありません。
書き間違えたサンプルは削除し、人が正解文字を確認します。

## ブラウザで追加学習

1. 用途を「追加学習用」に変えて、選択モデルに含まれる文字を2枚以上保存。
2. 別に「評価用」を1枚以上保存（実際の比較には文字別に十分な枚数が必要）。
3. ひらがな・カタカナのモデルから選び、「別モデルを追加学習」。特徴抽出層を固定し、出力層のみ学習率0.0001で5エポック学習。
4. 元モデルと学習後モデルを同じ評価用画像で比較し、「学習モデルZIP」で別名出力。
5. ZIPを展開し、model.json・weights.bin・labels.json・preprocessing.jsonを一緒に選び、収集画面の取込欄や、しりとり設定のファイル読込から試す。

学習はメモリ上の複製モデルで行い、元モデル・配信ファイル・ブラウザ内の元モデルを上書きしません。
GraphModelは推論用なので、同じCNN構造のLayersModelへ重みをコピーして追加学習します。
学習開始前に元モデルと複製の推論一致を検査します。取込モデルは認識・比較用で、追加学習の開始元は同梱3モデルです。
学習モデルは自動適用・自動永続化されません。ページを閉じる前にZIPを保存してください。
ZIPにはモデル、ラベル、前処理契約、学習元ID、学習・評価サンプルID、学習前後の結果を含めます。

画像の用途は保存時に固定され、評価用を自動で学習へ流用しません。旧データ（用途なし）は評価用です。
収集ZIPのmanifestと筆跡JSONにも用途を保存します。既存Colab評価取込は用途による絞り込みを行わないため、
Colabで独立評価するときは評価専用の記録IDを使い、学習に使用した画像を混ぜないでください。
この画面の学習と比較は現在の記録IDが対象です。同じ書き手への適応テストと、別の記録ID・端末での汎化評価を分けてください。
別の人の評価では、学習ZIPを取込み、記録IDを切り替えて「保存画像でモデルを比較」を実行します。
苦手文字だけの学習は他の文字を悪化させる可能性があります。清音も混ぜ、通常の筆跡を含む独立した評価セットで採否を判断します。

### 濁点・半濁点の合成配置について

旧v1は衝突時に右または上へ移動するため、実筆より離れて見える可能性がありました。
2026-10-18の配置v2では、本体の実際の墨線との距離を基準に、接触しない範囲で近い位置を80%、離れた位置を20%混ぜます。
更新したColabノートブックを再実行すると適用されます。実行中の旧ノートへは自動反映されません。
「ガ」「ゴ」「パ」「ポ」など字形の異なる文字を目視確認し、近い・離れた実筆を分けて評価して採否を決めます。
