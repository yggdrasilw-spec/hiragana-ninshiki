# 実筆画像の収集

`handwriting-capture.html` をブラウザで開きます。単独HTMLなのでダウンロードしてオフラインでも使えます。
スマホで利用する場合は同じファイルを配信するHTTP(S)ページを開きます。

1. カタカナ／ひらがな、文字のセット、１文字あたりの枚数を選ぶ。
2. 表示された文字を指・ペン・マウスで１文字ずつ書き、「保存して、次へ」。
3. 「画像をZIPで保存」で現在の記録ID・文字種類の全画像をダウンロードする。

カタカナは清音46＋濁音20＋半濁音5＋ヴの72文字、ひらがなは既存モデルと同じ71文字です。
初期設定はカタカナの濁音・半濁音26文字を３枚ずつ。文字ボタンで好きな文字へ移動できます。
進捗は保存した実際の枚数だけで計算し、スキップしても完了扱いにはしません。

筆跡と保存画像はIndexedDBで端末内に保存します。書きかけは文字・記録IDごとに保持します。
新しい人の記録は「新しい人」で開始し、以前の記録IDは入力欄の候補から選び直せます。
名前などの個人情報は不要です。ネットワークへのデータ送信は行いません。
ブラウザ保存が使えない場合は画面に表示し、その場でZIPへ書き出せるようにします。

## ZIPの内容

```text
ガ/<sample-id>.png
パ/<sample-id>.png
strokes/<sample-id>.json
manifest.json
README.txt
```

PNGは白背景・黒文字の256×256。補助線・お手本・案内文字は入りません。
元の正方形全体を保存し、切り抜きや64px化は評価ノート側で行います。
筆跡は0〜1の正規化座標、筆画内の経過時間、pointer種別、線幅を保存します。
manifestには正解文字・画像パス・記録ID・入力方法などを保存します。
ZIPのUTF-8パスとCRCは標準形式で、外部ZIPライブラリへの依存はありません。

## Colabで実筆評価

収集した `real-katakana-....zip` をColabへアップロードし、
`training/katakana/etl5_train_marks.ipynb` の⑧で次を設定します。

```python
REAL_ZIP = '/content/real-katakana-....zip'
```

⑧がZIPをローカルへ展開して評価します。全72文字がそろっていなくても評価でき、
未評価の文字を結果に残します。`real-` で始まるZIPは学習データの自動選択から除外します。
実筆テストに使った画像を追加学習へ使う場合、別の画像をテスト用に確保します。
ひらがなの収集ZIPは作れますが、今回の学習ノートの評価対象はカタカナです。

## モデル完成後の拡張要件

現時点では認識モデルを接続せず、選んだ文字の実筆を収集します。
濁点・半濁点対応モデルの完成後は、正解文字と認識結果を比較し、誤認識・未認識の筆跡だけを保存できるモードを追加します。
正解文字、上位候補とスコア、モデルの版、前処理の版、入力方法、記録IDを画像・筆跡と一緒に残します。
「ぬ」などの苦手な文字を指定して集め、追加学習に利用します。低スコアだけでなく、高スコアの取り違えも対象です。
これは認識器の改善用です。書字の正誤は別途人が確認し、正しい字を誤認識した例と、書き間違いを区別します。
誤認識例だけでは全体の認識率は測れないため、通常の筆跡も含む独立した評価セットを別に保持し、書き手単位で学習側と分けます。

### 濁点・半濁点の合成配置について

現在のローカル学習コードは配置を乱数で変え、衝突時に右または上へ移動して離します。
近づけ直す処理はなく、実筆より離れて見える可能性があります。進行中の学習条件は変更せず、完成モデルを実筆で評価します。
次回の比較候補は、本体の実際の墨線との距離を基準に、接触しない範囲で近い位置から離れた位置まで分布させる方式です。
「ガ」「ゴ」「パ」「ポ」など字形の異なる文字を目視確認し、近い・離れた実筆を分けて評価して採否を決めます。
