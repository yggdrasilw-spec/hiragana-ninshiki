# しりとり UI・UX / 敵対的レビュー

レビュー日：2026年10月7日。対象：`shiritori.html`、単語データ、画像表示、設定保存、ゲーム進行。変更はローカル。公開サイトへの反映は未実施。

## 今回の体験改善

- 入力欄の上に最近4語のチェーンを表示。読みの最初・最後の文字を発光するタイルで強調し、橋で接続する。
- 成功した単語が着地し、接続数が跳ね、短い粒子演出が出る。音オン時は上昇する3音を追加。実際にドーパミンが増えるかを測定したものではなく、成功の手応えを増やす設計。
- 次の文字と進行状況を入力画面で常時表示。スマホの強制タブ移動を廃止。単語カードを押すと説明を見られる。
- 次に必要な文字を入力欄の空表示に提示。確定ボタンと削除ボタンに日本語のアクセシブルな名前を追加。
- 低いコントラストを改善。フォーカスリング、短い画面でのスクロール、`prefers-reduced-motion`への対応。

## 残る指摘と改善順

### P1：先生向けロックは認証ではない

`unlockModeration()`の解除判定は配信HTML内の固定文字列であり、ロック状態もブラウザのlocalStorageにある。ソースを読んだりストレージを消したりできる利用者には解除可能。教室内の操作抑止としては使えるが、管理者認証として扱う設計は成立しない。本当の権限が必要なら、サーバー側で利用者・権限・解除処理を管理する。このレビューでは認証方式は変更していない。

### P2：テンポが説明の長さに支配される → 10月8日修正

通常は読みと35文字以内の第一義だけを読み上げ、4.5秒を上限にする。詳しい意味は説明欄の「このいみをきく」で任意再生（15秒上限）し、停止できる。音オフのCPU待ちは説明の長さによらず650ms、その後CPUの選択待ち600ms。音声の終了通知が来なくてもタイマーで待ちを解除し、リセットと音オフでも保留中の待ちを解除する。

### P2：終了時の罰が成功時より強い → 10月8日修正

「ん」終了で赤い警報・振動・ブザーを呼び出さず、つながったことを認める案内と再プレイ画面を表示する。再プレイ画面にも確定した語数を表示する。古いラウンドの終了タイマーが新しいゲームへ作用しないようラウンド番号を確認する。

### P2：CPUの語彙が辞書順に偏る → 10月8日修正

難易度・頭文字・使用済み・「ん」終わり設定に合う候補全体を重みづけ抽選する。重みは `1 + 3/level + 3/max(2,読みの長さ)`。短く難易度の低い語をやや優先しつつ、候補の末尾も選ばれる。「ん」語を選ぶ確率の設定は維持する。

### P2：説明の自動切替に操作手段が足りない → 10月8日修正

自動切替を廃止し「まえのいみ／つぎのいみ」を追加。意味・画像・クレジットは連動し、画像取得中に意味を切り替えた場合も現在の意味の画像を表示する。読み上げ再生・停止ボタンを追加。外部画像の関連性・適合性の全件確認は未実施。

### P3：初回起動が手書きモデルの準備を待つ

`initBackground()`は辞書・モデル・音声準備をまとめて待つ。モデルは外部TensorFlow配信にも依存する。ボタン入力だけで始めたい人も準備時間を負担する。辞書とボタン入力で先に開始し、手書きモデルの準備を後から知らせる構成が望ましい。
