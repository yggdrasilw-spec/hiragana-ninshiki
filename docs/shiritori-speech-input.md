# 設定から使う音声入力

入口は「せってい」→「文字入力」→「にゅうりょくのしかた」→「おんせい（補助）」のみ。表紙とゲームの通常入力タブには追加しない。文字に親しむ目的を保つため、かなを大きく表示し、手書き・ボタン・キーボードと併用する補助入力として説明する。

設定内の「聞き返し」で確認のオン・オフを切り替える。初期値はオン。オン・オフは `shiri-settings.speechConfirm` に保存する。オフは認識した読みを表示してそのまま既存の検証・接続に進み、「〜と認識」「オーケー」の対話を省略する。読みや認識候補が複数の場合は、未使用かつ次の頭文字につながる登録語を自動選択し、聞き返しがオンでもそのまま接続する。次の頭文字が未指定なら未使用の登録語を選ぶ。同じ条件の候補が複数残る場合は認識候補順、同一表記の読みは読みデータ順を優先する。語の重複・頭文字・「ん」のルール、無音、停止・再開は両方の設定で共通。設定を切り替えると確認中の語を取り消し、次の聞き取りから適用する。

「入力をうながす音声案内」は `shiri-settings.speechPrompt` に独立して保存する（初期値オン）。オフの場合、最初と各ターンの「ことばをひとつ」「〜からはじまることばをしゃべってください」という読み上げを省略する。画面の案内・次の文字の表示と、自動待機は維持する。読み上げ後の回り込みを避ける450msの待ち時間も維持する。確認、エラー・無音の再案内、終了後の案内はこの設定の対象外。

## 対話

1. 選択すると音をオンにし、ゲーム画面で案内を読み上げて聞き取りを開始する。初回はブラウザのマイク許可が必要。
2. 日本語の確定認識を待つ。認識器には最大5候補を要求し、返された候補の読みを登録語と照合する。短い語でも第2候補以降から拾える場合があるが、候補自体が返らない場合や全候補が誤認識の場合は復元できない。カタカナはひらがなに、漢字などは登録語の表記・読みデータから変換する。通常起動では読みデータを取得せず、漢字などが初めて返ったときに取得する。
3. 読み候補が一つで、聞き返しがオンの場合は「○○ と認識。よければ オーケー、ちがえば ちがうよ」と読み上げ、画面にも選択中のかな種で表示する。
4. 「オーケー／OK／はい」で既存の語の検証・接続に進む。「ちがうよ／違うよ／いいえ」では入力を消し、「もういちど、しゃべってください」と案内する。それ以外の返答では確定しない。
5. CPUと説明の読み上げが終わったら、次の頭文字を案内して自動的に聞き取りを再開する。語の重複や頭文字違いは読み上げて再入力に戻る。読みの候補をタップで選ぶ従来の補正パネルは、音声入力で確定する語には使わない。
6. 終了後は「もういっかい／もう一回」で児童から新しいゲームを開始する。音声モードでは聞き取り時に終了ポップアップを閉じ、案内と停止ボタンを見える状態にする。

## 停止・復帰

- 「おやすみ／ストップ」または停止ボタンで休止する。休止からは表示中の再開ボタンを使う。
- 無音は2回案内して待ち直し、3回続いたら休止。認識イベントが来ない場合は20秒で停止する。
- マイク拒否、通信エラー、読み上げ失敗や15秒の停滞は表示して停止する。読み変換の取得失敗は確定せず、言い直しを案内し、次回に再取得できる。
- アプリの読み上げ中とCPU処理中は聞かない。読み上げ終了から450ms空ける。認識器は単発・確定結果のみを使用する。
- 設定、別の入力、ダイアログ、リセットでは古い認識・変換結果を無効化する。別画面・タブへ離れると休止し、戻っても自動復帰しない。
- 音オフ／音量0でも休止し、再開ボタンで音をオンに戻せる。
- 通常の１人対CPUでは再読み込み後は手書きに戻す。複数人では各人の音声入力を保存・復元する。次の人が音声の場合、交代案内を読み終えてから受け取りタップを省いて自動的に次の聞き取りへ進む。入力方法を未設定の人は直前の音声入力を引き継ぎ、明示した手書き・ボタン・キーボードは維持する。非対応ブラウザでは手書きに戻す。停止・非表示による休止は交代しても解除しない。

ブラウザの音声認識サービスを使い、アプリは録音を保存しない。音声がサービス提供元に送られる場合がある旨を入口に表示する。対応状況・認識精度・許可の動作は端末とブラウザに依存する。実際の学校端末で、児童の発話、スピーカーの回り込み、通信・マイク許可を確認する必要がある。

## 読みデータと更新

`data/shiritori-speech-spellings.json` は JMdict の漢字表記・読みから抽出した補完データ。2026-10-05版の `jmdict-simplified` JSONを利用。元データのSHA256、抽出規則、出典URLを同ファイルに記録する。かなの表記制約に従い、よく使う読みがある語ではそれを優先し、稀な表記・検索用表記を除外する。ゲームへの語彙追加は行わない。

`data/shiritori-speech-readings.json` は登録語の表記と上記補完データを合わせた配信用データ。複数の読みがある漢字は、登録語・次の頭文字・未使用の条件から自動選択する。番号選択は行わない。条件に合う候補がない場合は言い直しを求める。空白・全角空白・改行は除去する。全体の表記が一致しない場合は、漢字部分の登録済みの読みとかな部分をつなげ、完成した読みが登録語に一致するときだけ候補にする（例：「国際 れんごう」→「こくさいれんごう」、「日本 こく 憲法」→「にほんこくけんぽう」）。複数の読みが残る場合は上記の自動選択を行い、探索量の上限を超えた場合は一つに決めず言い直しに戻す。辞書外の漢字や文章全体のかな変換には対応せず、かなをつなげて言い直す案内をする。

JMdict更新時（月次を目安）:

```powershell
python scripts/import-shiritori-speech-spellings.py <jmdict-simplifiedのJSONファイル>
node scripts/build-shiritori-speech-readings.cjs
```

`whitelist.csv` 更新時:

```powershell
node scripts/build-shiritori-speech-readings.cjs
node scripts/build-shiritori-speech-readings.cjs --check
```

`node tests/shiritori-speech-multiplayer-browser.cjs` は複数人の音声設定の保存・再読込、タップなし交代、他入力との混在、6人＋CPU、休止維持、交代読み上げ中のリセット、対戦の脱落・音声での再開、非対応ブラウザの復帰を1280/390/320pxで確認する。

既存の `tests/shiritori-delivery-browser.cjs` と `tests/shiritori-multiplayer.cjs` も確認する。
